1. Introduction

What is Cypress?

Cypress is a next-generation front-end testing tool built for the modern web. It enables you to write end-to-end tests, integration tests, and unit tests for your web applications.

Why Cypress for E2E Testing?

  • Fast & Reliable: Tests run directly in the browser with real-time reloading
  • Time Travel: See snapshots of your application at every step
  • Automatic Waiting: No need to add waits or sleeps to tests
  • Real-time Reloading: See results instantly as you write tests
  • Debugging: Readable errors and stack traces make debugging simple

Project Context

This guide documents the setup of Cypress in a Next.js 15 application with the following stack:

  • Next.js 15.5.3 with React 19
  • Redux Toolkit for state management
  • Supabase for authentication
  • Material-UI (MUI) for components
  • Vitest for unit testing (complementary to Cypress)

2. Installation & Setup

1Install Cypress Dependencies

Install Cypress and related testing libraries:

npm install --save-dev cypress @testing-library/cypress start-server-and-test

Package Breakdown:

  • cypress - The core Cypress testing framework
  • @testing-library/cypress - Cypress Testing Library commands for better selectors
  • start-server-and-test - Utility to start dev server before running tests

2Add NPM Scripts

Add the following scripts to your package.json:

"scripts": {
  "dev": "next dev --turbopack",
  "build": "next build --turbopack",
  "start": "next start",
  "test": "vitest",
  "cypress": "cypress open",
  "cypress:headless": "cypress run",
  "e2e": "start-server-and-test dev http://localhost:3000 cypress",
  "e2e:headless": "start-server-and-test dev http://localhost:3000 cypress:headless"
}
Script Description
cypress Opens Cypress Test Runner in interactive mode
cypress:headless Runs all tests in headless mode (no UI)
e2e Starts dev server and opens Cypress (most convenient)
e2e:headless Starts dev server and runs tests headlessly (CI/CD)

3. Configuration

3Create Cypress Configuration File

Create cypress.config.js in your project root:

const { defineConfig } = require("cypress");

module.exports = defineConfig({
  e2e: {
    baseUrl: "http://localhost:3000",
    setupNodeEvents(on, config) {
      // implement node event listeners here
    },
    specPattern: "cypress/e2e/**/*.cy.{js,jsx,ts,tsx}",
    supportFile: "cypress/support/e2e.js",
    video: false,
    screenshotOnRunFailure: true,
    viewportWidth: 1280,
    viewportHeight: 720,
  },
  component: {
    devServer: {
      framework: "next",
      bundler: "webpack",
    },
    specPattern: "cypress/component/**/*.cy.{js,jsx,ts,tsx}",
    supportFile: "cypress/support/component.js",
  },
});

Configuration Options Explained:

  • baseUrl - Base URL for your application (used with cy.visit())
  • specPattern - Glob pattern for test files
  • video: false - Disable video recording (saves space)
  • screenshotOnRunFailure - Take screenshots when tests fail
  • viewportWidth/Height - Default browser viewport size

4. File Structure

Create Support Files

Create the following directory structure:

cypress/ │ ├── e2e/ # E2E test files │ ├── home.cy.js │ ├── countries.cy.js │ ├── navigation.cy.js │ ├── favourites.cy.js │ └── authentication.cy.js │ ├── fixtures/ # Test data │ └── example.json │ ├── support/ # Helper files │ ├── commands.js # Custom commands │ ├── e2e.js # E2E support file │ └── component.js # Component support file │ └── tsconfig.json # TypeScript config

Support Files Content

cypress/support/e2e.js

// Import commands.js using ES2015 syntax:
import "./commands";

// Import Cypress Testing Library commands
import "@testing-library/cypress/add-commands";

cypress/support/commands.js

// Custom command for logging in (example using Supabase)
Cypress.Commands.add("login", (email, password) => {
  cy.session([email, password], () => {
    cy.visit("/login");
    
    // Wait for form to load and type email
    cy.get('input[type="email"]').should("be.visible").click().clear();
    cy.get('input[type="email"]').type(email, { delay: 50 });
    
    // Type password (re-query to avoid detachment issues)
    cy.get('input[type="password"]').should("be.visible").click().clear();
    cy.get('input[type="password"]').type(password, { delay: 50 });
    
    // Submit the form
    cy.get('button[type="submit"]').click();
    
    // Wait for successful login (redirect away from login page)
    cy.url().should("not.include", "/login", { timeout: 10000 });
  });
});

// Custom command to clear Supabase session
Cypress.Commands.add("logout", () => {
  cy.clearCookies();
  cy.clearLocalStorage();
  cy.window().then((win) => {
    win.sessionStorage.clear();
  });
});

5. Writing Tests

Basic Test Structure

describe("Feature Name", () => {
  beforeEach(() => {
    cy.visit("/path");
  });

  it("should do something", () => {
    cy.get('[data-testid="element"]').should("be.visible");
    cy.contains("Text").click();
    cy.url().should("include", "/expected-path");
  });
});

Example Test: Countries Page

describe("Countries Page", () => {
  beforeEach(() => {
    cy.visit("/countries");
  });

  it("should load the countries page", () => {
    cy.url().should("include", "/countries");
  });

  it("should display a list of countries after loading", () => {
    // Wait for countries to load
    cy.get('[data-testid="country-card"]', { timeout: 10000 }).should(
      "have.length.greaterThan",
      0
    );
  });

  it("should navigate to a country detail page when clicked", () => {
    // Wait for countries to load and click the first country card
    cy.get('[data-testid="country-card-button"]', { timeout: 10000 })
      .first()
      .click();

    // Verify navigation to detail page
    cy.url().should("include", "/countries/");
  });
});

6. Problems Encountered & Solutions

Problem 1: Elements Not Found

❌ Error Message:

AssertionError: Timed out retrying after 10000ms: 
Expected to find element: `[data-testid="country-card"]`, but never found it.

Root Cause

Tests were looking for data-testid attributes that didn't exist in the components. The tests were using selectors that didn't match the actual rendered HTML.

Initial Test Code (Broken)

it("should display a list of countries", () => {
  cy.get('[data-testid="country-card"]').should('exist');
});

Component Code (No Test IDs)

// Original component without data-testid
<Card key={country.name.common} sx={{ width: "200px", height: "200px" }}>
  <CardActionArea onClick={() => handleCountryClick(country.name.common)}>
    <CardContent>
      <Image src={country.flags.svg} alt={country.name.common} />
      <Typography variant="h6">{country.name.common}</Typography>
    </CardContent>
  </CardActionArea>
</Card>

✅ Solution: Add data-testid Attributes

Updated the component to include data-testid attributes for testing:

// Updated component with data-testid attributes
<Grid
  container
  spacing={2}
  direction="row"
  justifyContent="center"
  alignItems="center"
  data-testid="countries-grid"
>
  {countries.map((country) => (
    <Card
      key={country.name.common}
      sx={{ width: "200px", height: "200px" }}
      data-testid="country-card"
    >
      <CardActionArea
        onClick={() => handleCountryClick(country.name.common)}
        data-testid="country-card-button"
      >
        <CardContent>
          <Image
            width={100}
            height={100}
            src={country.flags.svg}
            alt={country.name.common}
          />
          <Typography variant="h6">{country.name.common}</Typography>
        </CardContent>
      </CardActionArea>
    </Card>
  ))}
</Grid>

Why data-testid is Better:

  • Tests don't break when CSS classes change
  • Clear intent - obvious which elements are for testing
  • More performant selector matching
  • Easier to maintain when component structure changes

Problem 2: Role Button Selector Not Found

❌ Error Message:

AssertionError: Timed out retrying after 10000ms: 
Expected to find element: `[role="button"]`, but never found it.

Root Cause

Material-UI's CardActionArea component doesn't always render with role="button". The test was assuming a semantic role that wasn't present.

Initial Test Code (Broken)

it("should navigate to a country detail page when clicked", () => {
  cy.get('[role="button"]', { timeout: 10000 }).first().click();
  cy.url().should("include", "/countries/");
});

⚠️ Alternative Approaches Tried:

  1. CSS Class Selector: .MuiCardActionArea-root - Works but fragile (breaks if MUI updates)
  2. Image Selector: img[alt] - Works but not semantic
  3. data-testid: [data-testid="country-card-button"] - Best solution!

✅ Solution: Use data-testid on CardActionArea

Added a specific data-testid to the clickable area:

// Updated test
it("should navigate to a country detail page when clicked", () => {
  cy.get('[data-testid="country-card-button"]', { timeout: 10000 })
    .first()
    .click();
  cy.url().should("include", "/countries/");
});

Problem 3: Input Value Not Persisting (Supabase Auth UI)

❌ Error Message:

AssertionError: Timed out retrying after 4000ms: 
expected '<input#email.supabase-auth-ui_ui-input>' 
to have value 'test@example.com', but the value was ''

Root Cause

The Supabase Auth UI input wasn't accepting typed values. The component needed proper focus and interaction before typing would work.

Initial Test Code (Broken)

it("should accept valid email format", () => {
  cy.get('input[type="email"]').type("test@example.com");
  cy.get('input[type="email"]').should("have.value", "test@example.com");
});

✅ Solution: Add Click, Clear, and Delay

The Supabase Auth UI inputs need to be properly focused and cleared before typing:

it("should accept valid email format", () => {
  cy.get('input[type="email"]')
    .should("be.visible")      // Wait for element to be visible
    .click()                   // Focus the input
    .clear()                   // Clear any existing value
    .type("test@example.com", { delay: 50 }); // Type with delay
  
  // Re-query to avoid detachment issues
  cy.get('input[type="email"]').should("have.value", "test@example.com");
});

Key Additions:

  • .should("be.visible") - Ensures element is ready
  • .click() - Properly focuses the Supabase Auth UI input
  • .clear() - Removes any pre-filled values
  • { delay: 50 } - Adds delay between keystrokes for dynamic forms

Problem 4: DOM Element Detachment

❌ Error Message:

CypressError: `cy.type()` failed because the page updated as a result 
of this command, but you tried to continue the command chain. 
The subject is no longer attached to the DOM, and Cypress cannot 
requery the page after commands such as `cy.type()`.

Common situations why this happens:
  - Your JS framework re-rendered asynchronously
  - Your app code reacted to an event firing and removed the element

Root Cause

The Supabase Auth UI re-renders its form components after user interaction, causing the DOM element to detach during a chained Cypress command.

Initial Test Code (Broken)

// ❌ Broken: Long command chain causes detachment
cy.get('input[type="email"]')
  .should("be.visible")
  .click()
  .clear()
  .type("test@example.com", { delay: 50 })
  .should("have.value", "test@example.com"); // Fails here!

⚠️ Why This Happens:

When you chain commands like .type().should(), Cypress keeps a reference to the original element. If the component re-renders (common in React apps with Supabase Auth UI), the element is replaced in the DOM, making the original reference stale.

✅ Solution: Break the Command Chain

Re-query the element after actions that might cause re-renders:

// ✅ Working: Break the chain by re-querying
cy.get('input[type="email"]')
  .should("be.visible")
  .click()
  .clear()
  .type("test@example.com", { delay: 50 });

// Re-query the element for assertion (new command chain)
cy.get('input[type="email"]').should("have.value", "test@example.com");

Updated Custom Login Command

Cypress.Commands.add("login", (email, password) => {
  cy.session([email, password], () => {
    cy.visit("/login");
    
    // Email: Clear first, then type (separate queries)
    cy.get('input[type="email"]').should("be.visible").click().clear();
    cy.get('input[type="email"]').type(email, { delay: 50 });
    
    // Password: Clear first, then type (separate queries)
    cy.get('input[type="password"]').should("be.visible").click().clear();
    cy.get('input[type="password"]').type(password, { delay: 50 });
    
    // Submit
    cy.get('button[type="submit"]').click();
    cy.url().should("not.include", "/login", { timeout: 10000 });
  });
});

Pattern to Remember:

For dynamic forms (especially Supabase Auth UI, React forms with state):

  1. Query element → Prepare (click, clear)
  2. Query element again → Type
  3. Query element again → Assert
Approach Result Use Case
Long command chain ❌ Fails Never use with dynamic forms
Break chain after .type() ✅ Works Dynamic forms, Supabase Auth UI
Use .then() callback ✅ Works Complex interactions
Alias with .as() ⚠️ Sometimes Static forms only

7. Best Practices

1. Use data-testid Attributes

✅ Good:

<button data-testid="submit-button">Submit</button>

cy.get('[data-testid="submit-button"]').click();

❌ Avoid:

<button class="btn-primary btn-lg">Submit</button>

cy.get('.btn-primary').click(); // Breaks when CSS changes

2. Wait for API Calls with Intercepts

it("should load countries from API", () => {
  cy.intercept("GET", "**/api/countries").as("getCountries");
  cy.visit("/countries");
  cy.wait("@getCountries");
  cy.get('[data-testid="country-card"]').should("exist");
});

3. Use cy.session() for Authentication

Cache authentication sessions to speed up tests:

Cypress.Commands.add("login", (email, password) => {
  cy.session([email, password], () => {
    // Login logic
  });
});

4. Clean Up Between Tests

beforeEach(() => {
  cy.clearCookies();
  cy.clearLocalStorage();
  cy.logout();
});

5. Use Appropriate Timeouts

// Default: 4 seconds
cy.get('[data-testid="element"]').should("exist");

// Custom timeout for slow-loading elements
cy.get('[data-testid="slow-element"]', { timeout: 10000 }).should("exist");

6. Break Chains for Dynamic Content

// ❌ Don't chain after .type() on dynamic forms
cy.get('input').type('text').should('have.value', 'text');

// ✅ Break the chain
cy.get('input').type('text');
cy.get('input').should('have.value', 'text');

7. Test User Flows, Not Implementation

✅ Good: Test user behavior

it("should allow user to add a country to favorites", () => {
  cy.visit("/countries");
  cy.get('[data-testid="country-card"]').first().click();
  cy.get('[data-testid="favorite-button"]').click();
  cy.visit("/favorites");
  cy.get('[data-testid="favorite-item"]').should("exist");
});

❌ Bad: Test implementation details

it("should dispatch addFavorite action", () => {
  // Don't test Redux actions in E2E tests
  cy.window().its('store').invoke('dispatch', addFavorite(country));
});

8. Running Tests

Interactive Mode (Development)

Open the Cypress Test Runner UI:

npm run cypress
# or with auto-start dev server
npm run e2e

Benefits of Interactive Mode:

  • See tests run in real-time
  • Time-travel through each command
  • Inspect DOM at any point
  • Use Chrome DevTools for debugging
  • Hot reload when tests change

Headless Mode (CI/CD)

Run all tests in the terminal:

npm run cypress:headless
# or with auto-start dev server
npm run e2e:headless

Running Specific Tests

# Run a specific test file
npx cypress run --spec "cypress/e2e/countries.cy.js"

# Run tests matching a pattern
npx cypress run --spec "cypress/e2e/**/*countries*.cy.js"

Running Tests in Different Browsers

# Chrome (default)
npx cypress run --browser chrome

# Firefox
npx cypress run --browser firefox

# Edge
npx cypress run --browser edge

# Electron (headless)
npx cypress run --browser electron

9. Advanced Topics

Custom Commands

Create reusable commands in cypress/support/commands.js:

// Custom command to login
Cypress.Commands.add("login", (email, password) => {
  // Implementation
});

// Custom command to wait for loading to complete
Cypress.Commands.add("waitForLoading", () => {
  cy.get('[data-testid="loading"]').should("not.exist");
});

// Use in tests
cy.login("user@example.com", "password");
cy.waitForLoading();

Environment Variables

Create cypress.env.json for environment-specific configuration:

{
  "apiUrl": "http://localhost:3000/api",
  "testUser": {
    "email": "test@example.com",
    "password": "password123"
  }
}

Access in tests:

const testUser = Cypress.env("testUser");
cy.login(testUser.email, testUser.password);

API Mocking with cy.intercept()

it("should handle API errors gracefully", () => {
  cy.intercept("GET", "**/api/countries", {
    statusCode: 500,
    body: { error: "Internal Server Error" }
  }).as("getCountriesError");

  cy.visit("/countries");
  cy.wait("@getCountriesError");
  cy.contains("Error loading countries").should("be.visible");
});

Component Testing

Test components in isolation:

import FavoriteButton from "@/components/FavoriteButton";

describe("FavoriteButton", () => {
  it("should toggle favorite state", () => {
    cy.mount(<FavoriteButton countryId="123" />);
    cy.get('[data-testid="favorite-button"]').click();
    cy.get('[data-testid="favorite-button"]').should("have.attr", "aria-pressed", "true");
  });
});

10. Troubleshooting Guide

Common Issues & Solutions

Issue Possible Cause Solution
Tests are flaky Race conditions, missing waits Add explicit waits, use cy.intercept(), increase timeouts
Element not found Element not rendered yet Add timeout, wait for API calls, check selector
Element detached from DOM Component re-rendered Break command chain, re-query element
Input not accepting value Input not focused, dynamic form Add .click() and .clear(), use delay option
Cypress won't start Port conflict, missing dependencies Check port 3000, reinstall Cypress

Debugging Tips

1. Use .debug() Command

cy.get('[data-testid="element"]')
  .debug()  // Pauses execution and opens debugger
  .click();

2. Use .pause() Command

cy.get('[data-testid="element"]')
  .pause()  // Pauses and shows "Resume" button
  .click();

3. Log to Console

cy.get('[data-testid="element"]').then(($el) => {
  console.log("Element:", $el);
  console.log("Text:", $el.text());
});

4. Take Screenshots

cy.screenshot("debug-screenshot");
cy.get('[data-testid="element"]').screenshot("element-screenshot");

5. Increase Logging

Set environment variable for verbose logging:

DEBUG=cypress:* npm run cypress

Performance Optimization

1. Disable Video Recording

In cypress.config.js:

module.exports = defineConfig({
  e2e: {
    video: false,  // Saves time and disk space
  },
});

2. Use cy.session() for Auth

Cache authentication to avoid repeated login:

cy.session("user-session", () => {
  cy.login("user@example.com", "password");
});

3. Run Tests in Parallel

Use Cypress Dashboard or CI/CD parallelization:

npx cypress run --record --parallel
